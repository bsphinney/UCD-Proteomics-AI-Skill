How the Report Was Made

The analysis report you received, and its audio discussion if it has one, were produced with Claude, Anthropic's AI model, following a set of written instructions and scripts the Proteomics Core maintains. Claude did not do the analysis itself. It called established proteomics software and the Core's fixed scripts, step by step, and those made every number. This page explains the difference, why it keeps the results the same from run to run, which parts an AI wrote, what people decided, and how your lab could run the same pipeline.

The short answer

Software

The numbers come from standard tools

DIA-NN, FragPipe or Sage searched the raw files, depending on the data type. R packages, usually limpa and limma, did the quantification and statistics; each report names the ones it used. Every number in the report comes from these, and the statistics can be re-run as plain R with no AI involved.

Claude

Claude ran the tools and wrote the words

Claude, working in Claude Code, ran each step by calling a script, read the tables and figures, and wrote the report text and, when there is one, the podcast script. It computes nothing itself (why that matters). Separate Claude reviewers check the podcast script, and the analysis too when it calls for an expert review.

Gemini

Google's Gemini makes the voices

When a report has a podcast, Gemini's speech model usually reads the script aloud in two synthetic voices. A second Gemini model then transcribes the audio back, so a script can confirm that every number was spoken correctly. If you would rather not use Google, a local voice can make the podcast instead (see below). Each report's "How this report was made" section says which voice made its podcast.

An AI that calls tools is not an AI that does the analysis

People often picture "AI analysed the data" as pasting a table into a chatbot and asking what changed. That is not what happens here, and the difference decides whether a result can be repeated.

An AI doing the analysis itself

The model reads the data and produces the answer from its own reasoning, or writes new analysis code each time it is asked.

  • Ask twice and the method can differ: another filter, another normalisation, another test.
  • A different model, or a newer version of the same one, makes different choices.
  • A number can be misread, rounded or invented, and nothing flags it.
  • There is no fixed record of what was done, so nobody can re-run it.

An AI calling tools, as this pipeline does

The model decides which step comes next and starts a program for it. The program does the work and writes the result to a file.

  • The method lives in scripts that ship with the skill. The same script, input and settings give the same output.
  • The settings come from a table in the skill, chosen by the data type, not from the model's memory.
  • The engines are pinned to one version per release of the skill.
  • Every command, version, input checksum and decision is recorded, so the run can be repeated without any AI.

What a tool call is

A language model produces text. In Claude Code, some of that text is a request to run a program on the computer: a "tool call". Claude Code runs the program and hands the output back to the model. The model never calculates a q-value or a fold change; it starts the program that does, then reads what the program wrote.

  1. Claude reads the procedure

    The skill is a written procedure. It names the script for each step and the rules Claude must follow.

  2. Claude calls the script

    One command, with the files and the answers you gave. The command is written to the run's log.

  3. The software does the work

    The script runs DIA-NN, R or another established tool, and writes tables, figures and a record of what ran.

  4. Claude reads the result

    It tells you what the script reported, passes on every warning, and moves to the next step.

One real call

You confirm

Claude shows these settings once, with their sources, and waits for your "go" before any computing starts.

Any Claude model, on any day, gets the same answer from that script, because the answer is in the skill and not in the model. The skill's own rule says a hand-written search command is never allowed, even for one quick search: the search always goes through the skill's search script, which records what ran.

What stays the same from run to run, and what does not

Run the same skill version on the same files with the same answers, and the parts made by software repeat. The parts written by an AI are worded differently each time, which is why they are checked against the parts that do not change.

What keeps Claude on the path

The skill version is checked first

Every conversation starts by checking which version of the skill is installed, and every report and bundle records the version that ran it.

One confirmation before computing

The engine and version, the mass accuracy and its source, the organism, the database, the design and the statistics are shown once. Nothing heavy runs before your "go".

Judgement calls belong to people

Which run is which sample, which runs to leave out, normalised or raw quantities: Claude asks, records your words, and never signs a decision itself.

Warnings are passed on, failures stop the run

Claude must relay every warning a script prints. A failed audit check stops the interpretation until it is resolved.

Everything is logged

Each command goes into commands.log, each decision into the decisions log, and the conversation itself is saved with the analysis, so a person or another AI can review what Claude did.

The scripts are tested

More than 6,000 automated tests run on every change to the skill. Before release 2.15, fresh Claude sessions ran the same request on the old and the new version on seven real datasets, and the results were compared.

In that comparison the two DIA datasets gave identical significant calls on both versions: five contrasts on a 15-run set, and a public benchmark with known ratios. A 77-run time course differed (one contrast went from 30 to 17 calls) and the cause was not isolated. The full table is in the CHANGELOG, "How it was checked".

What this does not guarantee

Claude still chooses which command to run and passes the answers into it, and it can make a mistake there, such as a wrong option or a skipped step. The skill cannot make that impossible. It makes it visible: the command log, the decisions log and the saved conversation show exactly what was run, and the bundle lets anyone run it again. Work done outside the skill's steps is recorded as such.

Nobody has yet run one dataset through the skill with several different AI models and compared the results. The design reason to expect the same numbers is above; a side-by-side test would be the proof.

Step by step

The pipeline is a Claude Code "skill": a written procedure with about 130 scripts, which Claude follows in order. Every analysis goes through the same steps, with or without statistics.

  1. Check the skill and the computer

    A script checks that the installed skill is current and, on first use, installs the tools it needs without administrator rights. You say where the heavy work runs: your own computer or a cluster.

    Software

  2. Read the raw files

    Scripts open the instrument files and work out the acquisition (DIA or DDA), the instrument, the m/z range and, for Orbitrap data, the resolution. If a script is not sure, it says so and you are asked.

  3. Ask what the files cannot say

    The organism, the type of experiment, the digestion enzyme, the sample type, and which sample belongs to which group. These are asked, never guessed from a folder or file name, and each answer is logged.

  4. Derive the settings and confirm once

    Scripts pick the engine and the search settings from the data type. Each value carries its source: measured from your files, a published recommendation, or a default marked as a default. You see them once and say "go".

  5. Get the pinned engine and build the database

    A script installs the engine version this release of the skill pins. Another downloads the proteome for your organism from UniProt, adds a contaminant set, and records the release and a checksum.

    Software

  6. Search the spectra

    DIA-NN 2.7.0 for DIA data (library-free, 1% FDR, match-between-runs); FragPipe 24.0 for timsTOF DDA-PASEF and for DDA with no enzyme rule; Sage 0.14.7 for other DDA. The search always goes through the skill's own search script, never a hand-written command. At the Core it runs as jobs on UC Davis's HIVE computing cluster.

    Software

  7. Watch the search

    A watcher script polls the jobs to the end, recognises known failures and stalls, and names the fix. Claude applies it and resubmits only what failed. A search that was interrupted is picked up where it stopped, not started again.

    SoftwareClaude

  8. Quantify and test

    limpa estimates each protein's amount and models missing values through a detection-probability curve instead of dropping or imputing them. limma tests each comparison with Benjamini–Hochberg FDR. Significance is the adjusted P value alone; there is no fold-change cutoff. Re-tests on complete data and with per-group variance flag which hits are robust. For a non-model organism, protein names come from DIAMOND searches against Swiss-Prot.

    A script first runs the statistics on normalised and on non-normalised quantities and compares them. When that check is not clear, a person decides which to use, not Claude.

    SoftwareYou

  9. Protein-set tests and figures

    When a comparison has few significant proteins, set tests (camera and fry, side by side, on sets chosen beforehand) are offered. An R script draws the QC plots, PCA, volcano plots and the top proteins.

    Software

  10. Audit for common mistakes

    A script checks the results for known pitfalls: too few replicates, a confounded design, mixed instruments, low depth, heavy missingness, contamination, unstable normalisation, implausibly large or empty results. Anything it finds goes into the report's "Audit & caveats" section. A failed check stops the run until it is resolved.

    Software

  11. Peak check

    Where it can run, Skyline draws DIA-NN's chromatogram peaks for the top proteins. It is a visual check of the peaks, not a second confirmation of the result.

    Software

  12. Write the report

    A script writes Claude a brief listing every table and figure to read. Claude reads them and the audit, then writes the text: the overview, answers to the lab's own questions, findings per comparison and the biological interpretation. A script assembles it with the figures into one HTML file and adds the "How this report was made" section from the run's records.

    Claude

  13. Expert review

    When a statistical claim goes to a collaborator, a result looks extreme (log2FC above 5, p below 10−10) or the organism is new, three separate Claude agents review the analysis independently, as a proteomics expert, a biologist and a statistician. Their points become the "Expert Review Notes" section.

    Claude

  14. Write the Methods

    A script writes the publication Methods from the instrument's own files and the run's records: the acquisition, the engine and the version that ran, the settings, the database, the statistics, and the instrument grant acknowledgment. A value no record holds is marked for you to confirm. Claude does not compose this text.

    Software

  15. Write the podcast script

    Optional. Once the report is final, Claude writes a conversation between two fictional hosts, a cell biologist and a statistician. It covers the results, how the samples were measured, and the key terms. Anything said that is not in the report is listed at the end of the transcript.

    Claude

  16. Check the script

    A script compares every number, gene-like symbol and capitalised name in the script with the report, and fails anything it cannot find. A separate Claude agent, not the one that wrote the script, then reads each sentence for overstatement and claims the robustness checks do not support.

    SoftwareClaude

  17. Make the voices

    Gemini's speech model reads the checked script in two voices (Kore and Charon). Only the transcript text is sent to Google. The report, tables and figures are not.

    Without Gemini, the open-source Kokoro model reads it instead, on the HIVE cluster, and nothing leaves campus.

    Geminior Local

  18. Listen back

    A Gemini text model transcribes the finished audio, and a script compares the transcript with the script. It warns if the word match falls below 0.93 (1 is perfect), if six or more words in a row were not heard, or if a number was not heard as written.

    For the local voice, two Whisper speech-recognition models on HIVE do the listening, and a misreading counts only where both hear it.

    Geminior LocalSoftware

  19. Build the reproducibility bundle

    A script collects what is needed to run the analysis again: the skill version, the engine build, a pinned software environment, the R session details, the settings, checksums of the inputs and outputs, the command log and a reproduce.sh. It lists anything it could not capture instead of leaving it out silently (more below).

    Software

  20. Package it

    One HTML file with the figures built in, so it opens offline; when there is a podcast, a second copy has the audio and the transcript built in too. Alongside it go a PDF, the tables, a README.html that lists every file, an AGENTS.md for the next AI assistant or person who opens the folder, and the files a PRIDE or MassIVE deposit needs. Re-running a result yourself

Every analysis leaves two things that let you repeat it without Claude. A result without both is treated as unfinished.

1. The analysis as plain R

reproducibility_log.R is the whole statistical analysis, top to bottom, with every value written out: the report it read, the cutoffs, the sample-to-group map, the design and the contrasts. It is written from the objects that actually ran, so it cannot describe a different analysis from the tables beside it. It needs only R with limpa and limma.

2. The whole run, pinned

The reproducibility/ folder holds the skill version, the engine build that ran, a locked software environment, the settings and the conditions file, checksums of the raw files, the database, the search report and the result tables, the command log, and a reproduce.sh that runs the search and the statistics again from the raw files.

How exact is "the same"?

  • Same software, settings, inputs and kind of processor: the result tables match to the last digit.
  • A different processor family: limpa's protein estimates can shift in about the third decimal place. In the Core's test across two processor families on its cluster, over 12 comparisons, no fold change moved by more than 0.0022 (log2) and no significance call changed. Each run records which processor it used.
  • A different number of threads: DIA-NN and Sage give the same output for a fixed version and thread count; another thread count can shift intensities slightly, so the count is recorded.
  • A database downloaded again later: UniProt will have moved on, and the entry count may differ by a few sequences. The recorded release and checksum show it.
  • A different skill version: the settings or the engine version may have changed on purpose. The CHANGELOG says what changed, and the re-analysis route compares the two.

Detail: the skill's reproducibility contract.

How the AI-written text is kept honest

An AI can write a fluent sentence that is wrong. The pipeline is built around that risk.

The AI does not make the numbers

Claude runs the tools and reports their output. It does not compute statistics itself (calling tools). The plain R script in the bundle re-creates every statistical result without Claude.

The factual sections are not AI-written

The Methods, the audit table and each report's "How this report was made" section are written by scripts from the run's records. A fact no record holds is left out or marked, never filled in.

The numbers sit beside the text

Claude is told to take every number in the report text from the result tables. The tables and figures are in the same report, so any sentence can be checked against them.

Every hit is re-tested

Each significant protein is tested again on complete data only, and again with each group allowed its own variability. The report leads with the hits that survive both.

Independent reviewers

The expert reviewers and the podcast's meaning check are separate Claude agents, not the one that wrote the text, so they do not share its assumptions.

Claude writes the script, a tool checks it

An early version let a model write the podcast straight from the report. It passed a number check yet still invented facts, such as calling limpa "our Core's custom extension to limma". Now Claude writes the script from the report it has read, and a script checks every number and name against the report.

What the checks cannot catch

The checks find invented numbers and names, not every wrong sentence. The automatic number check covers the podcast script; the report text has the rule and the reviewers, not a script. That is why the report and the audio both say the written report is the record. The audio is a guide to reading the report, not a replacement for it.

Running it in your lab

The skill is public and free to install. It is maintained by the UC Davis Proteomics Core and written for biologists: it installs its own tools without administrator rights, and confirms the plan with you before the long steps.

  1. Get Claude Code

    Anthropic's Claude Code runs on your own computer and needs a Claude subscription or an Anthropic API key.

  2. Install the skill

    In a terminal, one line, then start Claude Code:

    claude plugin marketplace add https://github.com/bsphinney/UCD-Proteomics-AI-Skill.git && claude plugin install ucdavis-proteomics-core-pipeline@ucdavis-proteomics-core

    Source and documentation: github.com/bsphinney/UCD-Proteomics-AI-Skill, folder skill/ucdavis-proteomics-core-pipeline. Current release 2.15.0.

  3. Ask in plain words

    Point Claude at a folder of raw files, for example:

    Analyze the proteomics data in /data/my_experiment. It's mouse liver, knockout vs wild type, four of each.

    Claude checks the files, asks about the organism and design, confirms the search settings once, then runs the search, statistics, figures, audit and report.

    Using another coding agent instead of Claude Code? Most of the skill is plain scripts that any agent able to run commands can follow, but this has not been tested. See what is specific to Claude Code.

  4. Add the podcast, if you want it

    It is optional and offered once the report is done. You choose the voice:

    • Gemini: you need your own Gemini API key. For unpublished data, use a key with billing turned on: under Google's Gemini API terms, free-tier content may be used to improve Google's products and read by human reviewers, and paid-tier content is not used that way.
    • Kokoro, the local voice (skill 2.14.0; for now Core members on HIVE): --tts local. No key, no consent form, nothing sent anywhere (details above).
    • macOS say: --tts say makes the audio offline with the Mac's built-in voices; it sends nothing, but nothing checks it automatically either.

    Cost: Google charges by length of audio. At the price checked on 16 October 2026, a 22-minute episode with Gemini 3.8 Flash TTS came to about 30 cents.

Where your data goes

  • Raw files are searched on your own computer or cluster. The files themselves are not sent to any AI service; Claude sees the scripts' summaries of them.
  • Claude sees what it reads while working: results tables, figures, logs and the report. Those go to Anthropic under the terms of your Claude plan. Check your institution's guidance for unpublished data.
  • Gemini receives only the podcast transcript, and then the audio for the listen-back check, and only if you make a podcast with Gemini voices. With the local voice or macOS say, nothing goes to Google.
  • Everything is recorded: each run keeps a log of the commands, the decisions, the software versions and which models made the audio, so you can say exactly what was done.
